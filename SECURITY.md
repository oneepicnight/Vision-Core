# Security Policy

## Reporting

Do not open a public issue containing exploitable details before coordinated
disclosure.

Use the repository owner's private contact method shown on the repository
hosting profile or request a private reporting channel from the repository
owner. No authoritative project security email address is currently published,
so this document does not invent one.

Include:

- affected version, commit, and platform;
- affected subsystem;
- reproduction steps or a minimal proof of concept;
- expected and observed behavior;
- potential impact;
- whether exploitation changes consensus, funds, availability, privacy, or
  network integrity;
- suggested mitigation, if known;
- your preferred coordination and credit details.

Avoid testing against systems or data you do not own or have permission to use.
Allow the maintainers time to confirm, remediate, validate, and coordinate a
release before public disclosure.

## Scope

Reports involving consensus divergence, transaction validation, PoW, VisionX,
P2P framing, denial of service, unsafe recovery, state corruption, secret
exposure, or unauthenticated administrative behavior are particularly useful.

This policy does not promise a bounty, response time, or support window.
